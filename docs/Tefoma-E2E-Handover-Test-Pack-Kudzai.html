1Objective and Go/No-Go rule

Run a complete business-process and role-based test of Tefoma Procurement to confirm:

  • All core procurement and stores workflows complete end-to-end with correct status transitions.
  • Role permissions are enforced — nobody can act outside their role.
  • The recently shipped features work: equipment details & photos on requisition lines, supplier alternative-part offers, price-revision negotiation, per-line split awards, multi-PO generation, re-sourcing of unawarded lines, GRV printing, and the stock-code import.
  • Audit and notification trails are complete and reviewable.
Go / No-Go rule
Handover proceeds only if all Priority 1 items pass (marked P1 in the master checklist) and no Critical or High defect remains open. Anything else is a NO-GO with a fix list.

Signing in — you will do this a lot

  1. Go to the system address. Choose Tefoma Staff (or Supplier Portal for supplier steps).
  2. Enter email and password.
  3. A 6-digit code is emailed to that address — fetch it and type it in. If it doesn't arrive within 30 seconds, check spam; if it expires, simply sign in again for a fresh one.
Ground rule
You are one person pretending to be many. The system deliberately stops one person doing everything — the requester cannot approve, the approver cannot pay. Keep one role in a normal window and another in an Incognito/Private window (Chrome Ctrl+Shift+N, Edge Ctrl+Shift+P) so two people stay signed in at once.
Record as you go
Write down every reference number the moment it appears — PR-2026-000xx, RFQ-2026-000xx, QT-2026-000xx, PO-2026-000xx, GRV-2026-000xx, invoice numbers. The audit-trail check at the end depends on them. Screenshot anything that looks wrong immediately (Win+Shift+S).

CPhase C — Core lifecycle: requisition → payment

90–120 minutes · Roles: all — this is the long walk through the whole system

The story: a JCB 3CX backhoe at a site has a leaking hydraulic pump. Nobody on site knows the part number, so the operator photographs the machine's data plate and attaches it. The supplier doesn't stock the genuine part and offers an equivalent. We also order A4 paper on the same requisition — deliberately, to prove office lines stay simple — plus one line that stores already holds, to exercise the issue-from-stock path.

C1–C4 · Requisition End user — james

  1. My Requisitions → + New Requisition. Title KUD-Hydraulic pump seal kit - JCB 3CX, urgency High.
  2. Item 1 (machine part): details Hydraulic pump seal kit, category Motor Vehicle Spares, Tyres & Accessories, qty 2.
    Watch closely — C2
    The moment you pick the vehicle-spares category, the grey “Equipment details & photos” panel must open by itself. Fill in Make JCB, Model 3CX Sitemaster, fleet no. FC-EX-014, registration, chassis/VIN, engine no., serial, hours 7450 — leave OEM part number blank (that's the realistic scenario). Add a photo, set its type to Data plate / serial plate, caption it.
  3. Item 2 (office): A4 Bond Paper, stationery category, 5 reams, spec 80gsm white. The equipment panel on this line must stay closed.
  4. Item 3 (in stock): one of the items you pre-loaded into inventory in B6.
  5. Submit for approval.
Expect — success message; requisition listed with status Pending HOD Approval; a PR-2026-000xx number. Open it: the seal-kit line shows every machine field as neat labelled lines with a clickable photo thumbnail that opens readable-size; the paper line shows no machine fields.
Report if — the panel didn't auto-open for vehicle spares; the photo vanished after saving; typing dropped letters in any box; machine fields appear on the paper line.

C11–C12 · Sealed bids, comparison & waiver Procurement — macdonald

DPhase D — New features deep-dive

60–90 minutes · These shipped recently and have had the least real-world exposure — test them hardest. Set up one fresh requisition with 4–5 line items and run it to a published RFQ (repeat C1→C8 quickly, no equipment details needed).

D1 · Price negotiation — request revision

  1. Supplier A quotes all lines. Procurement closes the RFQ, opens Supplier A's quotation and uses Request price revision with a reason and a target-price note.
  2. Supplier A — the portal shows “Revision requested — resubmit”. Submit a new quotation with lower prices.
  3. Procurement — open the new quotation: it should link back to the original; the old one is archived as superseded, with the revision history (round, who asked, why) visible.
Expect — D1a regression check — after the revision round-trip, the Quotations list page must load normally with the superseded and revision-requested quotes visible. (This page crashed on those statuses until a fix on 27 July — you are confirming the fix.)

D2 · Per-line split award — the Award Matrix

Have Supplier A quote lines 1–3 only and Supplier B quote lines 3–5 only (line 3 quoted by both; at least one line quoted by nobody). Close the RFQ.

  1. Procurement HOD — jb — open the RFQ's Award page. You should see a matrix: rows = RFQ lines, columns = suppliers, cells = quoted unit prices, blanks where not quoted. Select a winner per line with a justification — split them: some lines to A, some to B.
  2. Procurement — macdonald — authorize each line (the two-key control, now per line). Lines with fewer than 3 bids need a per-line waiver — complete one.
Expect — every line shows a status: awarded / unquoted / unawarded. A line cannot be authorized before HOD selection; a <3-bid line cannot proceed without its waiver.

D3 · Multi-PO generation

Procurement — Generate POs from the award map.

Expect — one PO per winning supplier, each carrying only that supplier's awarded lines at the awarded prices. Each PO independently enters the Phase C approval chain (approve at least one all the way through). The requisition must not flip to ordered/completed while any line is still unresolved.

D4 · Re-sourcing unawarded lines

Procurement — on the RFQ detail, find the unresolved lines panel (the line nobody quoted, plus any quoted-but-not-awarded). Use Re-source.

Expect — a new RFQ is created with its own RFQ number, containing only the unresolved lines, pre-inviting the same suppliers, linked back to the original requisition. (A 25 July fix targeted exactly this — the new RFQ failing to get a number. Confirm it.) The original lines are marked unawarded and cannot be re-sourced twice.

D5 · Stock-code import & bin locations Stores / Admin

The client's stock catalog (~Fossil stock codes) was bulk-imported. In Inventory:

  • Search for a handful of known stock codes from the source sheet — they should exist with correct description, unit and bin location.
  • Imported items carry zero on-hand quantity by design (import never invents stock and never overwrites existing balances) — confirm a few show 0 unless stock was received since.
  • Test the Import Excel button with a tiny 2-row file: re-importing an existing code must update it, not duplicate it.

Severity guide

  • Critical — blocks end-to-end completion, or a security/compliance control fails (e.g. sealed bids readable early, approval chain skippable).
  • High — major function broken with no practical workaround.
  • Medium — works partially; workaround exists.
  • Low — cosmetic or minor usability.
