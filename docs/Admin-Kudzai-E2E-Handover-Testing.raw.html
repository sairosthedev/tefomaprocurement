FossilProcure Full-System End-to-End (E2E) Handover Test Pack

Prepared for: Kudzai (kudzai@fossilzim.co.zw)
Role: System Administrator / UAT Owner
Purpose: Validate all critical workflows and controls before client handover
Date: 2026-07-29

1. Test objective

Run a complete business-process and role-based test of the full FossilProcure system to confirm:

  • All core procurement and stores workflows work end-to-end.
  • Role permissions are correctly enforced.
  • Supplier onboarding, RFQ, quotation, PO, delivery, invoice, and payment workflows complete without blockers.
  • Audit and notification trails are complete and reviewable.
  • The platform is ready for client handover.

Go/No-Go rule: handover can proceed only if all Priority 1 tests pass and no unresolved Critical/High defects remain.

2. Scope: what must be tested

Priority 1 (must pass)

  1. Authentication and OTP login for all roles.
  2. Admin setup: departments, sites, users, supplier activation readiness.
  3. End-user requisition to HOD approval.
  4. Stores issue/forward and inventory impact.
  5. Procurement RFQ creation and supplier invitation.
  6. Supplier quotation submission.
  7. Quote evaluation, selection, and PO creation.
  8. PO approval chain (HOD -> Finance -> COO when threshold is met).
  9. Supplier PO acknowledgement.
  10. Delivery receipt (GRV) and accept into stock.
  11. Invoice submission, finance approval, and payment recording.
  12. Notifications and audit log trace completeness.

Priority 2 (strongly recommended)

  1. Supplier KYS document workflow and verification status behavior.
  2. Supplier evaluations and analytics visibility.
  3. Store requisitions and stock transfers between sites.
  4. Budget page visibility and finance-role access checks.
  5. Reports visibility by role.
  6. Reject/cancel/waiver branches (negative and exception paths).

5. Execution plan (full system)

Phase A: Access and security checks (15-20 min)

  1. Sign in as admin (kudzai@fossilzim.co.zw) and verify OTP flow.
  2. Confirm staff login page and supplier login page are reachable.
  3. Confirm password reset flow opens and accepts a valid email.
  4. Verify role separation basics:
    • End user cannot access admin pages.
    • Supplier cannot access staff pages.
    • Finance cannot access admin-only maintenance pages unless intended.

Expected outcome: all logins work; no obvious permission leakage.

Phase B: Admin baseline setup checks (20-30 min)

  1. Admin -> Departments: create/update at least one test department.
  2. Admin -> Sites: verify Head Office and add a second site for transfer testing.
  3. Admin -> Staff Team: verify each required role account exists and is active.
  4. Admin -> Suppliers: verify at least 3 suppliers are active for RFQ competition tests.
  5. Admin -> Audit Logs: verify admin actions are recorded.

Expected outcome: master data is complete and auditable.

Phase C: Core end-to-end business flow (75-120 min)

Execute one requisition all the way to payment.

  1. End user creates requisition with:
    • one stock-catalog line,
    • one manual/free-text line,
    • realistic quantity and category values.
  2. Department head approves requisition (and separately rejects a throwaway requisition with reason).
  3. Stores reviews requisition:
    • issue in-stock line(s),
    • forward non-stock line(s) to procurement.
  4. Procurement creates RFQ from forwarded items and invites suppliers.
  5. Supplier submits quotation(s).
  6. Procurement reviews quotations and selects winner.
    • If fewer than 3 quotes, complete waiver path with reason.
  7. Procurement creates PO and submits for approval.
  8. HOD approves PO.
  9. Finance approves PO.
  10. COO approval branch:
    • test one PO below threshold (COO not required),
    • test one PO at/above threshold (COO required).
  11. Supplier acknowledges PO.
  12. Stores receives goods (GRV) and accepts into stock.
  13. Supplier submits invoice linked to PO.
  14. Finance approves invoice and records payment.
  15. Admin validates complete audit and notification trail for the transaction.

Expected outcome: end-to-end lifecycle completes with correct status transitions.

Phase D: Extended module checks (30-60 min)

  1. Supplier KYS flow:
    • upload documents,
    • verify checklist progress,
    • confirm activate/verify behavior.
  2. Supplier evaluation flow:
    • create an evaluation score,
    • verify score appears in analytics/performance.
  3. Stores extras:
    • test store requisition,
    • test stock transfer between two sites.
  4. Finance extras:
    • verify invoice state transitions,
    • verify payments ledger entry visibility.
  5. Reports and dashboards:
    • verify each role sees the correct report scope.

Expected outcome: non-core but business-critical modules are stable and role-correct.

Severity guide:

  • Critical: blocks end-to-end completion or security/compliance risk.
  • High: major function broken with no practical workaround.
  • Medium: function works partially; workaround exists.
  • Low: cosmetic or minor usability issue.
